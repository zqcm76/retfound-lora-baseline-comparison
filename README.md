# 青光眼眼底图像分析：眼底基础模型 vs 从零训练基线的受控对照

> **一句话**：在 REFUGE2 上，把「RETFound + LoRA 微调」和「从零训练的 ResNet34 / U-Net」放进**同一套评测口径**里做对照。
> 结论是：**分类任务上基础模型没有显著优于 ResNet34**，收益集中在视杯分割、vCDR 估计和概率校准。
> 这个负结果是本仓库要报告的主要内容之一，而不是被藏起来的东西。

**Controlled comparison of a retinal foundation model (RETFound + LoRA) against from-scratch baselines on REFUGE2.**
Under a single unified evaluation protocol — test set unsealed exactly once, thresholds calibrated on validation only,
bootstrap CIs on every metric, paired bootstrap for every model-to-model claim — the foundation model shows **no
significant classification gain** over a ResNet34 baseline. Gains appear in cup segmentation, vCDR estimation, and
calibration. A three-seed leave-one-camera-out study quantifies the cost of device shift directly.
Negative results are reported as-is.

## 1. 核心结果（REFUGE2 test，n=400，80 阳性 / 320 阴性）

| 任务 | 从零训练基线 | RETFound + LoRA | 配对检验 |
|---|---|---|---|
| 分类 AUC | **0.828** [0.775, 0.875] | 0.808 [0.751, 0.859] | Δ = −0.020 [−0.063, +0.021], p=0.345 → **不显著** |
| 概率校准 ECE ↓ | 0.339 | **0.168** | — |
| Brier ↓ | 0.281 | **0.166** | — |
| Disc Dice | 0.9300 [0.9176, 0.9397] | **0.9387** [0.9333, 0.9431] | 见 §3 |
| Cup Dice | 0.8123 [0.7992, 0.8238] | **0.8595** [0.8518, 0.8671] | 76.5% 的图像上更优 |
| vCDR MAE ↓ | 0.0803 [0.0743, 0.0866] | **0.0525** | −35% |
| 黄斑定位成功率 @1 视盘直径 | — | 0.905 | — |

方括号内为 2000 次 bootstrap 的 95% 置信区间。分类阈值全部在 **val** 上标定后冻结，再应用到 test。

> 上表所用的官方 test 集本身就来自一台**训练中未出现过的相机**（见 §5）。也就是说 0.808 这个数字
> 已经包含了一次设备漂移的代价，而不是分布内成绩——它与 LOCO 中未见相机 `device_b` 的 0.821 基本重合。

## 2. 这个仓库真正想展示的东西：评测口径

绝大多数「我复现了 XX 模型」的仓库，问题不在模型，在评测。本项目把评测纪律写进了代码：

| 约束 | 实现方式 |
|---|---|
| **test 只解封一次** | 所有超参、模型选择、阈值标定都在 train/val 完成；test 在流程末尾一次性跑完，跑完不回头重跑 |
| **阈值不许在评测集上拟合** | `--calibrate-on` 与 `--split` 相同时程序直接拒绝执行 |
| **每个数字都带不确定度** | AUC / Dice / MAE 全部报 bootstrap 95% CI；多 seed 实验另报跨 seed 标准差，两种不确定度不混用 |
| **模型对比用配对检验** | 同一批图像上做 paired bootstrap，输出 Δ 的 CI 与 p 值，而不是比较两个孤立的点估计 |
| **训练集 / 验证集不许伪装成测试集** | LOCO 中训练相机（Zeiss / Canon-A）与验证相机（Canon-B）分别因记忆和模型选择偏差被显式排除在跨设备结论之外（见 §5） |
| **没测就是没测** | 未实测的成本项写 `NaN`，不用占位符、不插补 |
| **单位不许混着比** | 黄斑误差同时以「图像边长」和「视盘直径」为单位报告，两者相差约 8 倍，代码里显式标注禁止并排比较 |
| **合成数据自检必须自曝** | dummy / synthetic 模式打印醒目横幅，产物不得进入任何报告 |
| **负结果照常报告** | 见 §3、§4、§5 |

完整执行顺序与每一步的注意事项见 [`RUNBOOK.md`](RUNBOOK.md)。

## 3. 分类与分割：收益到底在哪

### 分类：没赢，但概率变得可用了

基础模型的 AUC 点估计比 ResNet34 低 0.020，配对 bootstrap 的置信区间跨 0（p=0.345），
**在这个样本量下二者无法区分**。在匹配灵敏度 0.8625 的工作点上，ResNet34 的特异度反而更高（0.5875 vs 0.4750）。

唯一站得住的分类侧优势是**校准**：ResNet34 的 ECE 高达 0.339，意味着它输出的「概率」几乎不可解读，只有排序能用；
LoRA 版把 ECE 降到 0.168。**如果只报 AUC，这个差别会被完全掩盖** —— 这也是本仓库坚持同时报 Brier / ECE 的原因。

### 视杯：全面提升；视盘：不是「更准」，是「更少崩盘」

逐图配对后可以看到两种完全不同的提升模式：

| | Disc Dice | Cup Dice |
|---|---|---|
| 均值变化 | +0.009 | +0.047 |
| 优于基线的图像占比 | **39%** | **76.5%** |
| 中位数 | 0.9564 → 0.9506（略降） | 0.8334 → 0.8769 |
| 1% 分位 | 0.341 → **0.718** | 0.000 → **0.568** |
| Dice < 0.8 的失败图数 | 15 → **9** | — |

视杯是**全面提升**；视盘的均值提升**全部来自尾部**——典型样本上基础模型甚至略差，但把灾难性失败的样本救了回来。
准确的说法是「视盘分割更鲁棒」，不是「视盘分割更准」。这类区别只有做逐样本配对分析才看得见。

## 4. CDR 融合消融：四臂对照，结论是「没买到东西」

设计动机是把临床上诊断青光眼的核心指标 **vCDR（垂直杯盘比）** 显式注入分类头。四臂设计把两件常被混在一起的事拆开：
「是否引入 CDR」和「是否解冻分割分支」。

| 臂 | 可训练参数 | 分割是否解冻 | Disc Dice | 相对 `pure_e2e` 的 ΔAUC |
|---|---|---|---|---|
| `pure_e2e`（对照） | 0.26 M | 否 | 0.9311 | — |
| `pure_e2e_unfrozen` | 6.63 M | 是 | 0.9072 | +0.0017 [−0.0054, +0.0085] p=0.627 |
| `cdr_two_stage` | 0.27 M | 否 | 0.9311 | −0.0054 [−0.0135, +0.0019] p=0.160 |
| `cdr_soft`（梯度回传分割） | 6.63 M | 是 | 0.9036 | −0.0005 [−0.0082, +0.0068] p=0.891 |

三条结论：

1. **引入 CDR 对分类没有可测量的增益。** 在 test 上另做的对照（带/不带 CDR 融合头）同样只有 +0.004 AUC。
2. **解冻分割分支是负收益。** 可训练参数涨 25 倍，AUC 纹丝不动，Disc Dice 却从 0.9311 掉到 0.9072 ——
   分类梯度回传污染了分割分支。
3. 四臂的 `cdr_degenerate_rate` 均为 0，说明 CDR 分支没有退化成常数，**上面的「无增益」是真的无增益，不是实现 bug**。

> ⚠️ **口径说明**：四臂互相之间已确认对齐（两两 Pearson r > 0.94），可以横比。
> 但四臂的 `evidence_*.csv` 目前不含 `image_path`，因此**它们所在的 split 及与 §1 test 表的逐图对应关系尚未验证**，
> 在补齐之前其绝对 AUC 不得与 §1 的数字并列。
> 这一栏没有被悄悄抹掉，也没有被含糊过去——已知的边界就写在这里。

## 5. 跨相机泛化：LOCO（leave-one-camera-out，3 seed）

这是本仓库唯一真正做过**跨设备量化**的实验：每次留出一台相机的全部图像，用其余相机训练，只在留出的相机上评测；
整套流程跑 3 个随机种子（42 / 123 / 456）。代码见 `phase2/loco_runner.py`。

### 先说清楚 REFUGE2 的设备构成（文档里错得最久的一处）

| Split | 数量 | 相机 |
|---|---|---|
| Train | 1200 | Zeiss Visucam 500（400） **+ Canon CR-2（800）** |
| Val | 400 | 第三台相机（训练中未见） |
| Test | 400 | 第四台相机（训练中未见） |

**Canon CR-2 属于训练集。**「Train=Zeiss / Val,Test=Canon」是 **REFUGE1** 的结构，不是 REFUGE2。
这一条直接决定了下表哪几行能用。

### 结果

| 留出设备 | 角色 | AUC（mean ± SD, n=3） | 计入跨设备结论 |
|---|---|---|---|
| `canon_c` | 留出·同相机 —— **干净基线** | **0.9620 ± 0.0243** | ✅ |
| `device_a` | 留出·未见相机 | **0.9108 ± 0.0110** | ✅ |
| `device_b` | 留出·未见相机 | **0.8208 ± 0.0262** | ✅ |
| `canon_b` | **验证集**（模型选择集，存在乐观偏差） | 0.9777 ± 0.0152 | ❌ |
| `zeiss` | **训练集**（sanity check） | 0.9960 ± 0.0018 | ❌ |
| `canon_a` | **训练集**（sanity check） | 0.9962 ± 0.0012 | ❌ |

> **± 是 3 个 seed 的标准差，衡量训练随机性；它不是 AUC 的抽样不确定度**（那个是 §1 的 bootstrap CI）。
> 两者不可互换，且 n=3 的标准差本身估计很粗，只够看数量级。

<details>
<summary>各 seed 原始 AUC（供核对）</summary>

| 设备 | seed42 | seed123 | seed456 |
|---|---|---|---|
| `canon_c` | 0.9417 | 0.9889 | 0.9556 |
| `device_a` | 0.9153 | 0.9189 | 0.8984 |
| `device_b` | 0.8494 | 0.8147 | 0.7982 |
| `canon_a` | 0.9955 | 0.9956 | 0.9976 |
| `zeiss` | 0.9969 | 0.9940 | 0.9972 |
| `canon_b` | 0.9894 | 0.9606 | 0.9831 |

</details>

### 四条结论

1. **贵的不是「留出」，是「换相机」。** 以干净基线 `canon_c` 为参照做分解：
   训练集 0.996 → 同相机留出 0.962（−0.034）→ 未见相机 0.911 / 0.821（再 −0.051 / −0.141）。
   同型号相机换一台几乎不掉点，掉点集中发生在相机型号改变时。
2. **设备漂移的代价没有单一数值，取决于是哪台相机。**
   两台未见相机之间差 **0.090**，而 seed 标准差只有 0.011 / 0.026 ——
   **设备间差异比训练随机性大 3–8 倍**。只报一个平均掉点会掩盖最坏情况，
   而最坏的那台（`device_b`）同时也是最不稳定的（seed 间跨度 0.798–0.849）。
3. **§1 的 0.808 落在 `device_b` 的 0.8208 ± 0.0262 范围内。** 两者都是未见相机场景，
   进一步说明官方 test 的成绩已经付过设备漂移的代价，不存在「实验室里 0.99、换台机器才掉」的落差。
4. **0.996 是记忆，0.978 是模型选择偏差，两者都不是泛化指标。**
   早期版本曾把 Zeiss 的 0.998 当成「Canon-A → Zeiss 跨设备泛化」写进结果 ——
   这是本项目修正过的最严重的一处口径错误，保留在此以说明为什么 §2 要把
   「训练集 / 验证集不许伪装成测试集」写成一条硬约束。

### 这一节没测的东西

- **逐设备的分割指标未汇总。** 因此「几何结构比分类特征更抗设备漂移」这个文献里很常见的说法，
  在本仓库**没有证据支持**，不作声称。
- **未做逐设备的 bootstrap CI。** 上表的 ± 只反映 seed 间波动，不含每台相机上的抽样不确定度；
  各留出相机的样本量不同，`canon_c` 尤其小。

## 6. 成本

| | 从零训练基线 | RETFound + LoRA |
|---|---|---|
| 总参数 | 21.3 M（ResNet34）+ 7.8 M（U-Net） | ≈ 316 M |
| 可训练参数 | 29.1 M（100%） | **13.5 M（4.3%）** |
| 参数构成 | — | LoRA 1.18 M + pos_embed 0.59 M + 任务头 11.76 M |
| 训练耗时 | 小时级 | 7 GPU·h（RTX 3060 12GB） |
| 推理 | — | 41 ms / 图 |

LoRA 是**三任务共用的一份**（注入共享 backbone 的 qkv + proj），不存在「每个任务 X M 的 LoRA」这种说法。
11.76 M 任务头里约 73% 是分割解码器，分类头只有 0.004 M —— 这与 §1「分割强、分类平」的结果是自洽的。

一个诚实的成本-收益判断：**用 4.3% 的可训练参数和 7 GPU 小时，换来的是分割鲁棒性、vCDR 精度和概率校准，不是分类精度。**

## 7. 已知局限（请连同结果一起读）

1. **单数据集。** 全部结果来自 REFUGE2。§5 的 LOCO 提供的是**同一数据集内部的跨相机**证据，
   不等于跨数据集外部验证；报告中跨数据集的汇总列为 `NaN`（未测即留空，不臆造）。
   **本仓库不声称任何外部泛化能力。**
2. **样本量限制。** test 仅 400 图 / 80 阳性，AUC 的 95% CI 宽约 ±0.05；小于这个量级的差异本研究无法分辨。
3. **跨设备结论只覆盖 2 台未见相机，且二者差异达 0.09。** 用本仓库的数字去外推「换到第三台相机会掉多少」
   是不成立的——已观测到的范围是 0.05–0.14，样本太少不足以给出分布。
4. **分割评测分辨率不一致。** 基线在 512 评测、主模型在 384 评测，Dice 对分辨率敏感，两者不是严格同一把尺子。
5. **消融的绝对指标与 test 表不同源**，详见 §4 的警告。
6. **这不是临床工具。** Youden 工作点上 PPV = 0.39，即每 10 次阳性报警约有 6 次为假阳性；
   没有外部验证、没有前瞻性评估、没有监管路径。本仓库不构成任何医疗建议。
